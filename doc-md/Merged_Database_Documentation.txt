# SECTION 1: MASTER TABLES

1. COUNTRY

Description:
This table is master table of the countries that Canam deals with. Here we have data like why this country, scholarships and country name etc.

Main FK Relations with other tables:
None

14. LEAD_STUDENT_PREFERENCES

Description:
This table stores the data related to the 'lead_students' table. Here we have 
data like for which country lead student is interested in and assigned 
staff/advisor. Here a lead also can be assigned to multiple advisors (eg. in 
counsel_user_id or in user_id values can be: 2,45,3 or 3) but the maximum 
advisors can be assigned is 3 not more than that for now.

Main FK Relations with other tables:
- Linked with lead_students (col: lead_id): This id helps to link this table 
  with the 'lead_students'
- Linked with country (col: country_id): This column stores the student's 
  preferred country where the student is interested to go
- Linked with canam_staff (col: counsel_user_id): This column contains the 
  user ID of the staff to whom the student is assigned
- Linked with canam_staff (col: user_id): This column contains the user ID of 
  the staff member the student is speaking with. It can happen that a student 
  is assigned an advisor/staff member but encounters a different person in the 
  office. This column allows for tracking this. If it is the same person, the 
  IDs in the "counsel_user_id" and "user_id" columns will match

Table Structure:

TABLE `lead_student_preferences` (
  `id` int(11) NOT NULL AUTO_INCREMENT,

19. CANAM_STUDENT_ASSIGN

Description:
This table stores the data related to the assigned advisor track. Details like

advisor_assign_date etc. This table is similar to the 'lead_student_preferences' 
but the difference is where we track which advisor is assigned to the lead, 
similarly here we have which advisors are assigned to students. I am writing 
advisors here because a student can have multiple advisors assigned (eg. in 
counsel_user_id or in user_id values can be: 2,45,3 or 3) but the maximum 
advisors can be assigned is 4 not more than that for now. Here we have a column 
called advisor_assign_date which is the date when an advisor converts this lead 
into a student and also we have a column called counsel_date, this date is when 
the student gets counseled by the advisor and we also need to track for which 
country.

Main FK Relations with other tables:
- Linked with canam_branches (col: branch_id): By this we can know that the 
  student is associated with which branch
- Linked with canam_student_registration (col: student_id): This is connected 
  to the Canam student table which is the user table of the student where we 
  have the user login details and other details
- Linked with country (col: country_id): This column indicates the advisor's 
  consulting country, i.e. the country with which the advisor deals and also 
  this indicates that the student is counseled for this country
- Linked with canam_staff (col: counsel_user_id): This column contains the 
  user ID of the staff to whom the student is assigned
- Linked with canam_staff (col: user_id): This column contains the user ID of 
  the staff member the student is speaking with. It can happen that a student 
  is assigned an advisor/staff member but encounters a different person in the 
  office. This column allows for tracking this. If it is the same person, the 
  IDs in the "counsel_user_id" and "user_id" columns will match
