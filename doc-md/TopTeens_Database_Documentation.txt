# TopTeens Database - Complete Documentation
# Tables with Descriptions and Structures
#
# This document describes the database tables used by the TopTeens Django project.
# Use it to understand table structure, relationships, and to write queries.
#
# Conventions:
# - Table names: app_label + '_' + model_name (lowercase). E.g. blog_blog, users_user.
# - Many-to-many relations create extra tables (e.g. blog_blog_tags for Blog.tags).
# - Models inheriting BaseModel include: created, modified, object_status (soft delete).
# - object_status: 1 = active, other = deleted (filter with object_status=1 for active).
# - Actual column types may vary by DB backend (MySQL/PostgreSQL); check migrations if needed.

# SECTION 1: CORE MASTER & CONFIGURATION TABLES

1. CORE_CONFIGURATION

Description:
Stores key-value configuration used across the application (e.g. STUDENT_ID_PREFIX,
SCHOOL_STUDENT_ID_PREFIX). Values can be edited from admin. Soft-deleted rows are
excluded by default (object_status).

Main FK Relations with other tables:
None

Table Structure:

TABLE core_configuration (
  id integer NOT NULL AUTO_INCREMENT,
  created datetime(6) NOT NULL,
  modified datetime(6) NOT NULL,
  object_status smallint NOT NULL DEFAULT 1,
  key varchar(120) NOT NULL UNIQUE,
  value varchar(120) NOT NULL,
  editable tinyint(1) NOT NULL DEFAULT 1,
  PRIMARY KEY (id)
);

2. CORE_MASTERCLASS

Description:
Master table of school classes/grades (e.g. Class 6 to 12). Used for dropdowns and
filtering. value is numeric (6..12), label is display text (e.g. "Class 10").

Main FK Relations with other tables:
None

Table Structure:

TABLE core_masterclass (
  id integer NOT NULL AUTO_INCREMENT,
  created datetime(6) NOT NULL,
  modified datetime(6) NOT NULL,
  object_status smallint NOT NULL DEFAULT 1,
  name varchar(120) NOT NULL,
  value smallint unsigned NOT NULL UNIQUE,
  label varchar(64) NOT NULL,
  active tinyint(1) NOT NULL DEFAULT 1,
  PRIMARY KEY (id)
);

3. CORE_COUNTRY

Description:
Master table of countries. Used for location (colleges, users) and filtering.
Includes short_name and phone_code.

Main FK Relations with other tables:
- core_state (country_id): States belong to a country

Table Structure:

TABLE core_country (
  id integer NOT NULL AUTO_INCREMENT,
  created datetime(6) NOT NULL,
  modified datetime(6) NOT NULL,
  object_status smallint NOT NULL DEFAULT 1,
  name varchar(120) NOT NULL,
  short_name varchar(5) NOT NULL,
  phone_code varchar(5) NOT NULL,
  priority smallint unsigned NOT NULL DEFAULT 1,
  flag varchar(100) NULL,
  PRIMARY KEY (id)
);

Main FK Relations with other tables:

10. CORE_STATICPAGE

Description:

Main FK Relations with other tables:

Table Structure:

TABLE core_staticpage (

# SECTION 2: USERS AND AUTHENTICATION

13. USERS_USER (AUTH_USER_MODEL)

Description:
Main user table. Supports students, parents, institute, counselor, etc. (user_type).
EMAIL is USERNAME_FIELD. Includes name, mobile, image, referral, user_status,
is_demo_account, is_system_demo. Soft-deleted via object_status.

Main FK Relations with other tables:
- users_userprofile (user_id): One-to-one profile
- users_parentstudentlink: parent_id, student_id
- blog_blog (author_id): Blog posts
- Many other tables reference user_id for ownership or assignment

Table Structure:

TABLE users_user (
  id integer NOT NULL AUTO_INCREMENT,
  password varchar(128) NOT NULL,
  last_login datetime(6) NULL,
  is_superuser tinyint(1) NOT NULL DEFAULT 0,
  name varchar(255) NULL,
  email varchar(255) NULL UNIQUE,
  mobile varchar(25) NULL,
  is_active tinyint(1) NOT NULL DEFAULT 1,
  is_staff tinyint(1) NOT NULL DEFAULT 0,
  created datetime(6) NOT NULL,
  modified datetime(6) NOT NULL,
  object_status smallint NOT NULL DEFAULT 1,
  image varchar(100) NULL,
  is_completed tinyint(1) NOT NULL DEFAULT 0,
  referral varchar(255) NULL,
  user_type smallint NOT NULL DEFAULT 0,
  user_status smallint NOT NULL DEFAULT 0,
  is_demo_account tinyint(1) NOT NULL DEFAULT 0,
  is_system_demo tinyint(1) NOT NULL DEFAULT 0,
  PRIMARY KEY (id)
);

14. USERS_USERPROFILE

Description:
Extended profile for a user: birthdate, gender, schoolname, grade, and M2M to
hobbies, subject, figure_out (core models). One-to-one with User.

Main FK Relations with other tables:
- users_user (user_id): One-to-one
- core_hobbies (via M2M users_userprofile_hobbies)
- core_subject (via M2M users_userprofile_subject)
- core_userfigureout (via M2M users_userprofile_figure_out)

Table Structure:

TABLE users_userprofile (
  id integer NOT NULL AUTO_INCREMENT,
  created datetime(6) NOT NULL,
  modified datetime(6) NOT NULL,
  object_status smallint NOT NULL DEFAULT 1,
  name varchar(120) NULL,
  user_id integer NOT NULL UNIQUE,
  birthdate date NULL,
  gender smallint unsigned NOT NULL DEFAULT 1,
  schoolname varchar(250) NULL,
  grade varchar(100) NULL,

27. CAREER_EMBEDDINGS (db_table override)

Description:
Stores cached embedding vector (JSON) for a career for AI/semantic search.
One-to-one with Career. embedding_text_hash for cache invalidation; provider
and model_name identify the embedding model.

Main FK Relations with other tables:
- careers_career (career_id): One-to-one

Table Structure:

TABLE career_embeddings (
  id integer NOT NULL AUTO_INCREMENT,
  created datetime(6) NOT NULL,
  modified datetime(6) NOT NULL,
  object_status smallint NOT NULL DEFAULT 1,
  career_id integer NOT NULL UNIQUE,
  embedding json NOT NULL,
  embedding_text_hash varchar(64) NOT NULL,
  provider varchar(20) NOT NULL DEFAULT 'openai',
  model_name varchar(100) NOT NULL DEFAULT 'text-embedding-3-small',
  PRIMARY KEY (id),
  KEY (career_id),
  KEY (embedding_text_hash)
);
