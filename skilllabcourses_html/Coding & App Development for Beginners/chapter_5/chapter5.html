Section 1: What is Debugging? Common Errors in Code

What is Debugging?

Debugging is the process of finding, identifying, and fixing errors (called “bugs”) in your computer programs. Imagine you’ve built a cool robot, but it keeps spinning in circles instead of moving forward. Debugging is like opening up the robot, checking its wires and code, and figuring out why it’s acting weird. In coding, bugs can make your app crash, give wrong results, or just not work at all. The term “bug” comes from a 1947 incident where a moth was found stuck in a computer, causing a malfunction—hence, a “bug”!

For high school students like you, debugging is a superpower. It teaches patience, attention to detail, and creative thinking. Every time you fix a bug, you level up as a coder. Plus, it’s satisfying to see your program finally work after hunting down that pesky error!

Why Do Bugs Happen?

Bugs sneak into code for many reasons. Maybe you typed something wrong, misunderstood a concept, or didn’t plan your logic well. Don’t worry—every coder makes mistakes. The goal isn’t to avoid bugs (impossible!), but to get good at spotting and fixing them.

Common Errors in Code

Here are the three main types of errors you’ll encounter as a beginner, with multiple examples for each to help you recognize them:

  • Syntax Errors: These are like spelling or grammar mistakes in coding. You break the rules of the programming language, and the computer can’t understand your instructions.
    • Example 1: Forgetting a colon : after an if statement in Python.

if x == 5 # Error: Missing colon

print("Five!")

What Happens? Python throws a SyntaxError and stops running your code. Fix: Add the colon: if x == 5:

 

    • Example 2: Missing parentheses in a print statement (common in Python 2 to 3 transition).

print "Hello!" # Error: Missing parentheses in Python 3

What Happens? SyntaxError: Missing parentheses in call to 'print'. Fix: Add parentheses: print("Hello!")

 

    • Example 3: Incorrect indentation in a loop.

for i in range(3):

print(i) # Error: Indentation is wrong

What Happens? IndentationError: expected an indented block. Fix: Indent properly:

for i in range(3):

print(i)

 

  • Logic Errors: These are trickier because your code runs, but it doesn’t do what you wanted. It’s like telling your friend to meet at 3 PM, but they show up at 3 AM because you weren’t clear.
    • Example 1: Wrong condition in an Even or Odd Number Checker.

number = 10

if number / 2 == 0: # Error: Wrong logic, should use modulo %

print("Even!")

else:

print("Odd!")

What Happens? Output is wrong (says “Odd!” for 10). Fix: Use number % 2 == 0 to check the remainder.

number = 10

if number % 2 == 0:

print("Even!")

else:

print("Odd!"

 

    • Example 2: Incorrect calculation in a tip calculator.

bill = 50

tip = bill * 0.2 # Error: Logic assumes 20% tip, but user might want 15%

total = bill + tip

print("Total with tip: $", total)

What Happens? Always adds 20% tip, ignoring user preference. Fix: Ask for tip percentage.

bill = 50

tip_percent = float(input("Enter tip percentage: "))

tip = bill * (tip_percent / 100)

total = bill + tip

print("Total with tip: $", total)

 

    • Example 3: Wrong loop range for counting down.

for i in range(1, 5): # Error: Counts up instead of down

print("Countdown:", i)

print("Blast off!")

What Happens? Counts 1 to 4 instead of 5 to 1. Fix: Use range(5, 0, -1) to count down.

for i in range(5, 0, -1):

print("Countdown:", i)

print("Blast off!")

  • Runtime Errors: These happen while your program is running, often due to unexpected input or situations. It’s like baking a cake but forgetting eggs—everything crashes mid-process.
    • Example 1: Dividing by zero.

num = int(input("Enter a number: "))

result = 100 / num # Error: If user enters 0, crash!

print(result)

What Happens? If user enters 0, Python throws a ZeroDivisionError. Fix: Add a check.

num = int(input("Enter a number: "))

if num != 0:

result = 100 / num

print(result)

else:

print("Cannot divide by zero!")

 

    • Example 2: Accessing a list index that doesn’t exist.

friends = ["Alice", "Bob"]

print(friends[5]) # Error: Index 5 doesn’t exist

What Happens? IndexError: list index out of range. Fix: Check length or use a valid index.

friends = ["Alice", "Bob"]

if len(friends) &gt; 5:

print(friends[5])

else:

print("Index too high! List has only", len(friends), "items.")

    • Example 3: Converting invalid input to integer.

age = int(input("Enter your age: ")) # Error: If user enters "abc", crash!

print("Next year, you'll be", age + 1)

What Happens? ValueError: invalid literal for int() if input isn’t a number. Fix: Use try-except.

try:

age = int(input("Enter your age: "))

print("Next year, you'll be", age + 1)

except ValueError:

print("Please enter a valid number!")

Section 2: Techniques to Identify and Fix Bugs

Why Learn Debugging Techniques?

As a high school coder, you’re probably eager to build games, apps, or websites. But when bugs pop up, they can slow you down. Learning debugging techniques is like getting a toolbox—each tool helps you tackle a different problem. Let’s explore beginner-friendly methods with multiple examples to find and fix bugs in your Python code.

 

Technique 1: Read Error Messages Carefully

Python often tells you what’s wrong through error messages. When your code crashes, look at the last line of the error output—it usually points to the problem.

  • Example 1: Missing quote in a string.

print("Hello) # Error: Missing closing quote

Error Message: SyntaxError: unterminated string literal What to Do: The message says “unterminated string,” so check for missing quotes. Fix it: print("Hello")

  • Example 2: Undefined variable.

print(my_name) # Error: Variable not defined

Error Message: NameError: name 'my_name' is not defined What to Do: Define the variable first. Fix it: my_name = "Alex"; print(my_name)

 

Technique 2: Use Print Statements to Track Values

Logic errors often hide, so use print() statements to check variable values or confirm if code blocks run.

  • Example 1: Debugging a grade calculator.

score = 85

print("Score is:", score) # Check value

if score &gt; 90:

grade = "A"

elif score &gt; 80:

grade = "B"

print("Grade assigned:", grade) # Confirm grade

print(f"Your grade is {grade}")

Practical Tip: Place print() at key spots (after inputs or inside loops) to see where things go wrong. Remove them once fixed.

  • Example 2: Checking a loop’s progress.

total = 0

for i in range(1, 6):

total += i

print("Current i:", i, "Current total:", total) # Track each step

print("Final total:", total)

What Happens? You see each addition (1+2+3+4+5) to spot if total is wrong.

 

Technique 3: Break Down Your Code

If your program is long, test small chunks. Comment out parts with # or run just one section to isolate the bug.

  • Example 1: Testing a loop separately.

# Test this loop alone first

for i in range(5):

print(i)

# Later, add the rest of the code

  • Example 2: Isolating input logic in a game score tracker.

# Test input first

player_score = int(input("Enter score: "))

print("Score entered:", player_score)

# Comment out complex logic for now

# if player_score &gt; high_score:

# high_score = player_score

# print("New high score!")

 

Technique 4: Use a Debugger Tool (Simplified for Beginners)

Many coding environments like IDLE, VS Code, or Thonny have a “debugger” feature. It lets you run code line by line and watch variables change. For now, just know it’s like a slow-motion replay of your code. Ask your teacher to show you how to “step through” code in your editor—it’s a game-changer!

 

Technique 5: Rubber Duck Debugging (Fun for Teens!)

Explain your code line by line to a rubber duck, a friend, or yourself out loud. Talking through it helps spot mistakes.

  • Why It Works: Saying “Wait, why did I write this if condition?” forces rethinking.
  • Example: If debugging a loop that doesn’t stop, explain: “I set i to 0, add 1 each time, but forgot to limit it!” Fix by adding a condition.
  • Teen Twist: Grab a funky toy or snack and “teach” it your code. Laugh, but watch how often this works!

Coding Sequence 1: Debugging a “Pizza Order Calculator”

Let’s debug a buggy program—a “Pizza Order Calculator” that’s not working. Follow these steps:

  • Buggy Code:

topping = input("Enter a topping: ")

if topping = "pepperoni": # Bug 1: Wrong operator

price = 2.50

elif topping == "cheese"

price = 1.50 # Bug 2: Missing colon

else:

price = 0

print("Total cost: $" + price) # Bug 3: Type mismatch

  • Error Messages: Run it. Python says SyntaxError at line 4 (missing colon). Fix it: Add : after "cheese".
  • Next Bug: Run again. Crashes on line 2, no error message, but nothing happens. Check logic: = should be ==. Fix it.
  • Final Bug: Run again. TypeError on line 7 because price is a number, not a string. Fix it: print("Total cost: $" + str(price)).
  • Final Code:

topping = input("Enter a topping: ")

if topping == "pepperoni":

price = 2.50

elif topping == "cheese":

price = 1.50

else:

price = 0

print("Total cost: $" + str(price))

 

Coding Sequence 2: Debugging a “Homework Timer”

Let’s debug another program—a “Homework Timer” with multiple issues.

  • Buggy Code:

  • Error Messages: Run it. SyntaxError for missing colon. Fix it: Add :.

  • Final Bug: Logic might be wrong—should it be &gt;=? Test and decide.
  • Final Code:

if time_spent &gt;= time_limit:

print("Take a break!")

Practical Explanation

Debugging isn’t magic—it’s systematic. Start with error messages, use print() to spy on variables, test small parts, and talk through code. For teens, think of it as troubleshooting a game glitch: check settings, restart, try different moves. Same vibe with code!

 

Section 3: Testing Code for Accuracy and Efficiency

What is Testing, and Why Do It?

Testing means running your program with different inputs to ensure it works correctly (accuracy) and doesn’t waste time or resources (efficiency). Imagine you’ve coded a quiz app for friends. If it gives wrong scores or takes forever to load, they’ll ditch it! Testing catches issues before anyone else does.

Types of Testing for Beginners

  • Manual Testing: Run your code with different inputs yourself.
    • Example 1: For a grade calculator, enter scores like 95, 75, 55, and weird inputs like -5.
    • Goal: Check if outputs match expectations.
    • Example 2: For a chat app greeting, test inputs like “Alex”, “”, or “123”. Does it handle empty or odd names?
  • Edge Case Testing: Try extreme or unexpected inputs to see if code breaks.
    • Example 1: In a number-guessing game, what if someone enters letters? Add a fix:

try:

guess = int(input("Guess a number: "))

except ValueError:

print("Please enter a number, not text!")

    • Example 2: Test a savings app with huge numbers (999999) or negatives (-50). Does it crash or give weird results?
  • Efficiency Check: Does your code take too long or use too much memory? For beginners, notice if it feels “slow.”
    • Example: A loop printing 1 to 1,000,000 numbers lags. Limit to 1 to 10 for testing.

    • Normal: Savings = 50, Price = 30 → “You can buy the game!”

    • Bad: Savings = “abc” → Crashes with ValueError. Fix with try-except.
  • Improved Code:

try:

savings = float(input("Enter your savings ($): "))

game_price = float(input("Enter game price ($): "))

if savings &gt;= game_price:

print("You can buy the game!")

else:

print("Save more! You need $", game_price - savings, "extra.")

Test a program deciding if you have enough snacks for a movie night.

  • Code to Test:

snacks_per_person = 2

print("Invalid input! Enter numbers only.")
