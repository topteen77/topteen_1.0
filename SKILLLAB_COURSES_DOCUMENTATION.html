Overview


This documentation covers the complete implementation of the Skill Lab Courses learning system, including admin panel enhancements, course learning interface, progress tracking, and data management tools.


Key Components

  • Admin Panel: Enhanced filtering, status display, and preview functionality
  • Learning Interface: Interactive course learning with chapter-by-chapter progression
  • Progress Tracking: User-specific completion tracking for chapters and activities
  • Data Management: Import scripts and verification tools for course data

2. Course Category Assignment


Automatic Category Detection

Courses are automatically assigned categories based on keywords in their names:


  • After 10th Class (after_10_class): Keywords like "class 7", "class 8", "career ready"
  • After 12th Class (after_12_class): Keywords like "class 12", "after 12", "soft skills"
  • After College (after_college): Keywords like "college", "graduate", "post-graduate"
  • Both (BOTH): Default fallback category

Implementation:

  • get_course_category() method in import script
  • Category assignment during course import
  • Separate management command for updating existing courses

Files:

  • skilllab/management/commands/import_skilllab_courses.py
  • skilllab/management/commands/update_skilllab_course_categories.py

Progress Tracking


Model: `SkillLabCourseProgress`


Tracks user progress through Skill Lab Courses:



class SkillLabCourseProgress(BaseModel):
    user = ForeignKey(User)
    skilllab_course = ForeignKey(SkillLabCourse)
    chapter = ForeignKey(SkillLabCourseChapter, null=True, blank=True)
    completed = BooleanField(default=False)
    completed_at = DateTimeField(null=True, blank=True)
    
    class Meta:
        unique_together = (('user', 'chapter'),)

Features:

  • Tracks completion status per chapter
  • Records completion timestamp
  • Unique constraint prevents duplicate progress records
  • Indexed for performance

Migration: skilllab/migrations/0003_skilllabcourseprogress.py



Chapter Locking Logic


Chapters are locked and unlocked based on sequential completion:


  1. First Chapter: Always unlocked
  2. Subsequent Chapters: Unlocked only when previous chapter is completed
  3. Activities: Locked if their parent chapter is not completed

Implementation:

  • chapter_locked_status dictionary in view context
  • Calculated based on user's progress records
  • Visual indicators in sidebar (lock icons)

URL Namespace Fixes


Issue

Multiple files were using incorrect namespace 'skilllab:' instead of 'skilllabcourse:', causing NoReverseMatch errors.


Solution

Replaced all instances of 'skilllab:' with 'skilllabcourse:' across:


Python Files:

  • skilllab/views.py
  • skilllab/models.py
  • skilllab/document_filters.py

Template Files (17 files):

  • templates/template20/home_new.html
  • templates/template20/skilllab_course_detail.html
  • templates/topteenfrontend/skillabcoursechapter.html
  • And 14 other template files

Correct Namespace Usage


All URL references should use:


# Python
reverse('skilllabcourse:skilllabcourselist')
reverse('skilllabcourse:skilllabcoursedetail', args=[slug])

# Templates (Jinja2)
{{ url('skilllabcourse:skilllabcourselist') }}
{{ url('skilllabcourse:skilllabcoursedetail', args=[course.slug]) }}


Technical Implementation Details


View: SkillLabCourseLearningView


Location: skilllab/views.py


Key Methods:

  • get(): Main view method that:
  • Retrieves course and chapters
  • Determines current chapter/activity from query params
  • Calculates progress and lock status
  • Prepares context for template

Context Variables:

  • course: Current SkillLabCourse object
  • chapters_list: All chapters for the course
  • current_chapter: Currently displayed chapter
  • current_activity: Currently displayed activity
  • activities_list: Activities for current chapter
  • chapter_progress: Dictionary of chapter completion status
  • chapter_locked_status: Dictionary of chapter lock status
  • progress_percentage: Overall course progress (0-100)
  • next_chapter: Next chapter object (if available)


API Endpoint: MarkChapterCompleteView


URL: /skilllabcourse/mark_chapter_complete/

Method: POST

Authentication: Required (login_required)


Request Body:


{
  "chapter_id": 42,
  "course_id": 1
}

Response (Success):


{
  "status": "success",
  "message": "Chapter marked as complete",
  "chapter_id": 42,
  "created": true,
  "next_chapter_id": 43,
  "course_slug": "ai-future-work-preparedness"
}

Response (Error):


{
  "status": "error",
  "error": "Error message here"
}

Implementation:

  • Uses SkillLabCourseProgress.objects.update_or_create()
  • Automatically determines next chapter
  • Returns next chapter ID for automatic navigation

function navigateToActivity(activityId, chapterId) {

  window.location.href = currentUrl + "?type=activity&id=" + chapterId + "&activity_id=" + activityId;
}

Database Schema


SkillLabCourseProgress Table



CREATE TABLE skilllab_skilllabcourseprogress (
    id INT PRIMARY KEY AUTO_INCREMENT,
    user_id INT NOT NULL,
    skilllab_course_id INT NOT NULL,
    chapter_id INT NULL,
    completed BOOLEAN DEFAULT FALSE,
    completed_at DATETIME NULL,
    created_at DATETIME NOT NULL,
    modified_at DATETIME NOT NULL,
    UNIQUE KEY (user_id, chapter_id),
    INDEX (user_id, skilllab_course_id),
    INDEX (user_id, chapter_id),
    FOREIGN KEY (user_id) REFERENCES users_user(id),
    FOREIGN KEY (skilllab_course_id) REFERENCES skilllab_skilllabcourse(id),
    FOREIGN KEY (chapter_id) REFERENCES skilllab_skilllabcoursechapter(id)
);

Error Handling


Common Issues and Solutions


1. NoReverseMatch: 'skilllab' is not a registered namespace

Solution: Ensure all URL references use 'skilllabcourse:' namespace


2. ProgrammingError: Table doesn't exist

Solution: Run migrations: python manage.py migrate


3. Duplicate slug errors during import

Solution: Import script automatically handles by appending counter (e.g., course-slug-1)


4. Character encoding errors

Solution: Import script uses BeautifulSoup to clean HTML content before saving


5. CSRF token errors

Solution: Template includes hidden CSRF input field, JavaScript reads it for AJAX requests
